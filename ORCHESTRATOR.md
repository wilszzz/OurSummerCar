# OurSummerCar Orchestrator Guide & Multi-Agent Protocol

Руководство по оркестрации разработки многопользовательского мода **OurSummerCar** (MSC Multiplayer) на базе модульной архитектуры C# / .NET 3.5 / Unity 5.0.0f4 / MSCLoader.

---

## 1. Концепция и правила оркестратора

Оркестратор (Coordinator) управляет командой специализированных агентов (Subagents / Swarm Workers). Каждая игровая механика разрабатывается в **изолированном модуле** (`OSC.Module.<Name>`), который компилируется в отдельную динамическую библиотеку (`OSC.Module.<Name>.dll`).

### Золотые правила архитектуры:
1. **Полная изоляция модулей:** Модули **НИКОГДА** не ссылаются друг на друга напрямую. Любое межмодульное взаимодействие происходит исключительно через шину событий `OscEventBus` и маршрутизатор пакетов `PacketRouter` в `OSC.Core`.
2. **Нулевая статическая связь загрузчика:** `OSC.Bootstrap` (`OurSummerCar.dll`) **НЕ ИМЕЕТ** статических ссылок на `OSC.Core` или модули. Это предотвращает фатальную ошибку `ReflectionTypeLoadException` в MSCLoader при старте игры. Все сборки модулей загружаются динамически из папки `Mods/Assets/OurSummerCar/Modules/`.
3. **Единый владелец физики (Ownership):** Никакого спама пакетов с обеих сторон (пинг-понга). У каждого объекта или механизма есть один явный владелец в данный момент (через `OwnershipRegistry`).
4. **Соблюдение ограничений движка:** Unity 5.0.0f4 (старый Mono 2.0 runtime, C# 9.0 с TargetFramework `net35`).
   - `Transform.SetPositionAndRotation` **НЕ СУЩЕСТВУЕТ** (появился в 5.6) — задавать `.position` и `.rotation` раздельно.
   - `Vector3.SignedAngle` **НЕ СУЩЕСТВУЕТ** — использовать `Mathf.DeltaAngle` или `Vector3.Angle` с векторным произведением.
   - `Physics.autoSimulation` **НЕ СУЩЕСТВУЕТ**.
   - Не перезаписывать каждый кадр трансформы объектов, которыми управляет нативный PlayMaker FSM игры, если это приводит к дёрганью; вместо этого переключать состояния FSM через события или делать `Rigidbody.isKinematic = true` на удалённых клиентах при плавной интерполяции.

## 2. Актуальный статус проекта (Ревизия кода)

### ✅ УЖЕ РЕАЛИЗОВАНО В `src/` (Собрано, 0 ошибок):
1. **`OSC.Core` + `OSC.Bootstrap` (`OurSummerCar.dll`):**
   - Динамический загрузчик без статических зависимостей.
   - `NetworkTransport` (Steamworks P2P), `PacketRouter`, `PacketIO`, `OwnershipRegistry`, `OscEventBus`, `PlayMakerBridge`, `SceneHasher`.
2. **`OSC.Module.Players.dll` (Этап 1):**
   - 3D-модель и одежда (`CharacterAssetLoader`), скелет/IK (`AnimatorSyncer`, `FastIKFabric`), локальный трекер анимаций.
   - Выход из прыжка при приземлении (фикс застывания), приседание, жесты, мочеиспускание, ругательства.
3. **`OSC.Module.TimeWeather.dll` (Этап 1):**
   - Время 1:1 (часы и минуты, стрелки `SuomiClock`), погода, облака, 5-секундная отложенная досинхронизация для late-join.
4. **`OSC.Module.WorldDoors.dll` (Этап 1):**
   - Межкомнатные двери дома, гаражные ворота (левая/правая створки) с кинематической интерполяцией в `FixedUpdate`.
5. **`OSC.Module.Items.dll` (Этап 2):**
   - Подбор/бросок предметов (`PickUp`/`Drop`), ящики пива и нативная бутылка в левой руке куклы (`hand_left/beer_bottle`), расходники, пакеты магазина (`ShoppingBag`), канистры, инструмент, домкрат/кран (`GarageAndToolsSync`), сканер чит-спавна (`ScanCheatSpawnedItems`).
6. **`OSC.Module.Vehicles.dll` (Этап 2):**
   - Базовая физика шасси для всех 9 видов транспорта (`Satsuma`, `Hayosiko`, `Ruscko`, `Ferndale`, `Kekmet`, `Gifu`, `Jonnez`, `Flatbed`, `Boat`).
   - Водительские места и кастомная система пассажирских сидений (`PassengerSeatSystem` с опусканием куклы Hayosiko на `0.08f`), синхронизация руля, толкание авто руками (`Hand Push` / `J`), защита от коллизий с кузовом (`CollisionAndExitGuard`), перехват чит-телепортов.

## 3. Совместимость с BetterCheatBox и сторонними модами

Большинство игроков и тестеров используют **BetterCheatBox**. Любой модуль обязан учитывать его влияние:

1. **Мгновенная телепортация (Teleport):** дельта `> 10m` за кадр -> отключать Lerp, мгновенный Snap, сброс скорости Rigidbody и `Physics.SyncTransforms()`.
2. **Спавн предметов (Item Spawner):** сканер `ScanCheatSpawnedItems` в `OSC.Module.Items` регистрирует новые объекты вокруг игрока.
3. **Автосборка Сацумы и болты:** `OSC.Module.Satsuma` периодически проверяет `SceneHasher` и шлёт полный снимок (Full Snapshot) при резком скачке.
4. **Чит на топливо и жидкости:** скачок `> 0.5L` рассылается напарнику как принудительная заправка.
5. **NoClip:** плавная интерполяция куклы без спама анимации падения/прыжка.

## 4. Регламент работы оркестратора

1. **Постановка задачи:** чётко указывать целевой модуль `OSC.Module.<Name>`, ссылку на соответствующий легаси-файл как референс логики и ограничения Unity 5.0.0f4.
2. **Изоляция:** никаких прямых ссылок между модулями — мосты только через `OscEventBus` и `PacketRouter`.
3. **Сборка:**
   ```powershell
   dotnet build src\OurSummerCar.sln -c Release --no-restore
   ```
   *(Требование: 0 ошибок, 0 предупреждений, авто-деплой в `Documents\MySummerCar\Mods\`).*
4. **Git и проверка:** после каждого этапа коммит в `main` и обязательный чек-лист **«Что проверить в игре»**.
